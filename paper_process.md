## Abstract
>The automotive industry trends to softwarizing cars according to flexible, service-oriented architectures. 
At the same time, connected cars become networked computer systems but lack proper security architectures. 
In this paper, we propose to authenticate and authorize in-vehicle services by integrating DNSSEC, DANE, and DANCE with automotive middleware. Our approach decouples the cryptographic authentication of the service from that of the service deployment with the help of DNSSEC and thereby largely simplifies key management. 
We propose to authenticate in-vehicle services by certificates that are solely generated by the service suppliers but published on deployment via DNSSEC TLSA records solely signed by the OEM. 
We further show how these well-established Internet standards secure service discovery and invocation, ensure interoperability with various protocols, and scale management of credentials for millions of connected vehicles at robust security levels. 
We back our design proposal by a security analysis using the STRIDE threat model and by evaluations in an emulation of a realistic in-vehicle setup that demonstrate its effectiveness.

## Project Overview
This project contains the following components for running experiments of SOME/IP using DNSSEC for service authentication. 

1. vsomeip: 
    - A Fork of the [COVESA vsomeip](https://github.com/COVESA/vsomeip) implementation branched November 2023.
    - We add different build configurations that all include statistics recording (see Measurement and Data Collection) for time-based service discovery metrics. **Vanilla** mirrors the exact vsomeip basis, **service and client authentication** add our handshake for mutaual authentication, **encryption** adds a key exchange that allows for subsequent sending of encrypted payloads, **DNSSEC - DANE - DANCE** enable lookup of client and service credentials from a DNS server. 
    - Service configurations are autogenerated into the vsomeip-configs directory, e.g., extended from vsomeip-configs/vsomeip-udp-mininet-publisher.json, for each network host.
2. nsd (DNS Server): 
    - a light-weight DNS server from [nlnetlabs](https://nlnetlabs.nl/projects/nsd/about/)
    - Configurations are adapted at runtime and stored in nsd directory.
    - DNS zones are auto generated during scenario setup into the zones directory.
3. Mininet: 
    - Network emulation on the host system using [mininet](https://mininet.org/)
    - Multiple synthetic scenarios: topo-1sw-Nhosts.py for 1 publisher with X subscribers each on their own node; topo-1sw-multipubsub.py for various setups with multiple publishers and subscribers and common or separate nodes.
    - A full in-vehicle network in the carnet directory with different configurations to run. The paper uses results from topo-carnet-hostperservice.py
